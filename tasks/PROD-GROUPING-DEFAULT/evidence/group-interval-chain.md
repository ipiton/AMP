# Живой бинарь: цепочка `group_interval`

- Дата: 2026-10-10, ветка `bugfix/prod-grouping-default`, код `83c3d12`.
- Бинарь `cmd/server` локально, `profile: lite`, без ключа `grouping:` в конфиге; webhook-приёмник на `127.0.0.1` печатает время каждой доставки.
- Маршрут: `group_by: [alertname]`, `group_wait: 2s`, `group_interval: 5s`, `repeat_interval: 1h`.

## Сценарий

| Время (скрипт) | Действие |
|---|---|
| +0.0 с | POST `ChainProbe`, `instance=i1` |
| +9.2 с | POST `ChainProbe`, `instance=i2` (после первого тика `group_interval`, ожидаемого на ~+7 с) |
| +31.3 с | остановка |

## Доставки (часы приёмника, запущен на ~1.6 с раньше первого POST)

```text
t=+  3.63s status=firing alerts=['i1:firing']
t=+ 13.66s status=firing alerts=['i1:firing', 'i2:firing']
```

## Вывод

- Первая доставка — через `group_wait` после первого алерта.
- Вторая доставка — через 10.03 с после первой, то есть на втором тике `group_interval`; `i2` ждал её ~2.9 с, меньше одного `group_interval`. До починки цепочки второй алерт уходил бы только по `repeat_interval` (1 ч).
- На первом тике (группа не изменилась) и на трёх тиках после второй доставки (до +31 с) повторов нет: всего две доставки.
- Смещение часов приёмника относительно скрипта (~1.6 с) оценено по первой доставке, отдельно не измерялось; интервал между доставками от него не зависит.
